# Primitive IO — v0.3.0 Dropbox Output 仕様書

- 文書版: v0.3.0
- 作成日: 2026-09-24
- 状態: 実装仕様（未実装）
- 対象: Firefox / ChatGPT Web / Dropbox

## 1. 概要

v0.3.0 は、既存の Cloud Explorer に Dropbox Output を追加する。利用者は Dropbox の保存先フォルダとベースファイル名を選び、Primitive IO が既存ファイル名を基に自動決定したバージョン付きファイル名で、ChatGPT へ「この会話の議論内容を要約して新規保存する」依頼を投入する。

Output の対象は Dropbox だけとする。GitHub は入力専用であり、GitHub リポジトリやファイルを出力先・出力候補として扱わない。

Primitive IO は Dropbox のファイル本文を取得・生成・保存・送信しない。Dropbox への実際の書き込みは、利用者が別途接続した ChatGPT 側 Dropbox 連携が利用可能な場合だけ行われる。Primitive IO は保存依頼のプロンプトを作るだけで、ChatGPT または Dropbox による保存成功・失敗を判定しない。

## 2. 背景と利用者価値

会話で設計、調査、議論を行った後、その内容を Dropbox のプロジェクトフォルダへ残したい場合がある。会話から保存先フォルダと新規ファイル名を毎回正確に伝える操作は煩雑である。

Dropbox Output は、Cloud Explorer のツリーから保存先を明示選択し、既存ファイル群と衝突しにくいバージョン付きファイル名を表示する。利用者は保存依頼前に対象フォルダと最終ファイル名を確認できる。

## 3. 前提と非保証事項

- 利用者は ChatGPT 側で Dropbox を接続し、書き込みアクションが使えるアカウント、プラン、ワークスペース設定、権限を持つ必要がある。Primitive IO 側 Dropbox OAuth と ChatGPT 側 Dropbox 連携は別の認可である。
- ChatGPT 側で Dropbox 書き込みが利用できない、承認が必要、または保存に失敗する場合がある。Primitive IO はその結果を読まず、成功表示もしない。
- Primitive IO は Dropbox のファイル本文、生成された要約、保存結果、download URL を取得・保存しない。
- バージョン番号の算出後に、別端末・別利用者・別アプリが同名ファイルを作成する競合は完全には防止できない。Primitive IO は Dropbox へ直接書き込まないため、原子的な「存在しなければ作成」は提供しない。
- ChatGPT がこの会話の内容をどの範囲で参照・要約するか、および Dropbox アクションを実行するかは ChatGPT 側の責務である。

## 4. 機能要件

### 4.1 Output の対象と内容

- Output は Dropbox だけを対象とする。GitHub Explorer のリポジトリ、ファイル、選択状態を Output UI に表示・利用しない。
- v0.3.0 の保存内容は固定で「この会話の議論内容を要約した文書」とする。ユーザー登録の定型プロンプト選択は将来機能であり、v0.3.0 には含めない。
- 保存操作は `保存を依頼` と表示する。`保存`、`保存完了`、`保存しました` のように実書き込み成功を示す文言は使用しない。
- `保存を依頼` を押した後は、プロンプトを投入したことだけを表示する。共通の `autoSend` が有効な場合は、そのユーザー操作を起点としてだけ送信する。

### 4.2 アクティブフォルダ

- Dropbox ツリーのフォルダには、展開・折りたたみとは別に `保存先にする` 操作を表示する。フォルダを展開しただけではアクティブフォルダを変更しない。
- アクティブフォルダは視覚的に強調し、Output UI に `保存先: /project/primitive-io` の形式で Dropbox root 基準の表示パスを示す。
- `パスをコピー` は、表示中の Dropbox root 基準パスだけをクリップボードへコピーする。トークン、ファイル本文、会話内容はコピーしない。
- アクティブフォルダの内部参照には Dropbox folder ID を使い、表示とプロンプトには API 応答の表示パスを使う。利用者入力から保存先パスを組み立てない。
- アクティブフォルダ、出力用ファイル名、読み込み済み候補は ChatGPT ページのライフサイクル中だけ保持する。ページ再読込・遷移、Dropbox 更新、Dropbox 接続解除で破棄する。
- アクティブフォルダ未選択時は Output の保存依頼操作を無効にする。

### 4.3 ベースファイル名と入力候補

- 新規出力では、利用者がベースファイル名を入力する。空文字列、空白だけの名前、`/` を含む名前は拒否する。
- 上記以外の文字・拡張子に Primitive IO 独自の制限を設けない。Dropbox または ChatGPT 側の制約で保存できない場合は、ChatGPT 側が報告する。
- Dropbox Input で Primitive IO の読み込みプロンプトを正常に投入したファイルは、同じページ内だけ出力名候補にする。候補選択時は元ファイルの名前をベースファイル名欄へ設定する。
- 候補はファイル名を補助するだけであり、上書き先や出力対象を示さない。選んだ入力ファイルの親フォルダを保存先へ自動変更しない。
- Dropbox Input で選択しただけで、読み込みプロンプトを投入していないファイルは候補にしない。

### 4.4 自動バージョン付与

保存依頼の直前に Primitive IO はアクティブフォルダを再取得し、その直下のファイル名を使って最終ファイル名を決定する。再取得が失敗した場合は保存依頼を行わず、エラーを表示する。

1. 入力ファイル名を `stem`、末尾の拡張子を `extension` として扱う。拡張子がなければ `extension` は空文字列とする。
2. `stem` の末尾が `-v` に続く0以上の整数である場合（例: `議事録-v2.md`）、その整数を入力バージョンとし、`-v<number>` を除いた部分をベースstemとする。該当しない場合、入力バージョンは0、ベースstemは入力stemとする。
3. アクティブフォルダ直下にある `ベースstem-v<number>extension` と完全一致する通常ファイルの最大バージョンを求める。フォルダ名、非ファイル、別拡張子、別の命名形式は数えない。
4. 最終バージョンは `max(入力バージョン, 既存最大バージョン) + 1` とする。最終ファイル名は `ベースstem-v最終バージョンextension` とする。

例:

| 利用者入力 | アクティブフォルダの既存名 | 最終ファイル名 |
| --- | --- | --- |
| `議事録.md` | なし | `議事録-v1.md` |
| `議事録.md` | `議事録-v1.md` | `議事録-v2.md` |
| `議事録-v2.md` | `議事録-v1.md` | `議事録-v3.md` |
| `議事録-v2.md` | `議事録-v5.md` | `議事録-v6.md` |
| `メモ` | `メモ-v1`、`メモ-v2` | `メモ-v3` |

計算済みの最終ファイル名は編集不可で表示し、保存依頼の直前に再計算する。ChatGPT にバージョン番号の決定、同名ファイル探索、代替名の選択を委ねない。

### 4.5 保存依頼プロンプト

アクティブフォルダと有効なベースファイル名がある場合だけ `保存を依頼` を有効にする。プロンプトには、Dropbox root 基準の保存先と Primitive IO が決定した最終ファイル名をそのまま入れる。

```text
Dropbox 連携を使って、この会話での議論内容を要約し、次の新規ファイルとして保存してください。
既存ファイルは上書きしないでください。指定したファイル名以外の代替名を決めないでください。

保存先フォルダ: /project/primitive-io
ファイル名: 議事録-v3.md
```

- 既存の `insertTextIntoEmptyComposer` を再利用する。下書きがある入力欄は上書きせず、中止理由を表示する。
- `autoSend` がオフなら投入だけを行う。オンなら、利用者が `保存を依頼` を押した場合だけ投入後に送信を試行する。
- 保存依頼プロンプトを投入しても、Dropbox Input または GitHub Input の選択状態を解除しない。

## 5. UI 要件

Cloud Explorer の Dropbox 表示に `Output` セクションを追加する。

```text
▼ 📁 primitive-io                     [保存先にする]
   📄 議事録-v2.md

Output
保存先: /project/primitive-io [パスをコピー]
ベースファイル名: [ 議事録.md              ]
保存ファイル名: 議事録-v3.md
                     [ 保存を依頼 ]
```

- アクティブフォルダは通常のフォルダ色と区別し、`保存先` ラベルを表示する。
- 最終ファイル名の計算中は保存依頼ボタンを無効にし、`保存ファイル名を確認中…` を表示する。
- アクティブフォルダの再取得失敗、ファイル名不正、ChatGPT入力欄の下書き、送信失敗は、Dropboxパネル内のOutput通知で区別する。
- `保存を依頼` 後の通知は、auto-send オフでは `保存依頼のプロンプトを入力欄へ投入しました。送信はしていません。`、オンでは `保存依頼のプロンプトを投入して送信を試行しました。` とする。Dropbox保存の成功・失敗を表す通知は出さない。

## 6. 実装設計

### 6.1 ファイル構成と責務

```text
src/
├─ background/
│  ├─ dropboxClient.ts       # 既存の直下一覧取得を再利用。書き込みAPIは追加しない
│  └─ index.ts               # 新しい出力専用messageは原則不要
├─ content/
│  ├─ dropboxExplorer.ts     # アクティブフォルダ、名前候補、バージョン計算、Output UI
│  ├─ chatgptAdapter.ts      # 既存の下書き保護・投入・送信を再利用
│  └─ index.ts               # 変更不要
└─ options/
   └─ index.ts               # 共通auto-sendを再利用。Output固有設定はv0.3.0では追加しない
```

- バージョン計算は副作用のない関数として切り出し、ユニットテスト可能にする。
- アクティブフォルダ再取得には既存の `primitive-io:dropbox-list-folder` を使う。ファイル本文API、アップロードAPI、書き込みHTTPメソッド、追加Dropbox OAuth scopeは使用しない。
- Dropboxの既存ツリー取得キャッシュは閲覧用に保持するが、保存依頼直前の番号計算では必ず最新の直下一覧を取得する。
- 出力候補は `DropboxEntry` のID・名前・パスだけをメモリへ持つ。トークン、本文、ChatGPT回答、Dropboxの書き込み結果は保存しない。

### 6.2 状態遷移

```text
未選択
  └─ フォルダを保存先にする → アクティブフォルダ
       └─ ベース名を入力/候補選択 → ファイル名計算
            └─ 保存を依頼 → プロンプト投入
                 └─ auto-send ON の場合だけ送信試行
```

Dropbox更新、接続解除、ページ再読込・遷移は、アクティブフォルダ・計算済みファイル名・候補を `未選択` へ戻す。Dropbox/GitHubのクライアント切替およびCloud Explorerの開閉は、Dropbox Outputの状態を解除しない。

## 7. セキュリティとプライバシー

- Primitive IO の Dropbox OAuth scope は既存の `files.metadata.read` と `account_info.read` を維持し、`files.content.write`、`files.content.read`、共有・削除・書き込み権限を追加しない。
- Dropbox API通信は既存の `api.dropboxapi.com` のメタデータ取得だけとし、ファイル本文・upload URL・書き込みレスポンスを取得しない。
- 保存先パスと最終ファイル名は、利用者が `保存を依頼` を押した時だけ ChatGPT の入力欄へ投入する。
- 会話の要約内容は Primitive IO が抽出・送信するのではなく、ChatGPT が会話コンテキストを基に生成する。利用者は保存依頼前に、会話内容がChatGPT側Dropbox連携によって保存対象になり得ることを認識する。
- `パスをコピー` はユーザー操作を起点とし、保存先表示パスだけをクリップボードへ書き込む。
- ChatGPT側Dropbox連携の権限、保存可否、保存結果はPrimitive IOから検証・制御しない。

## 8. テスト仕様

### 自動テスト

- バージョン計算: バージョンなし、既存なし、連番、入力済みバージョン、既存最大バージョン、拡張子なし、日本語・空白・記号名を確認する。
- 入力検証: 空文字、空白だけ、`/` を含む名前を拒否し、それ以外の名前を受け付ける。
- Output UI: 保存先未選択時の無効化、明示的フォルダ選択、候補のページ内保持・更新時破棄、最終名表示を確認する。
- プロンプト: 新規作成・上書き禁止・保存先・確定済みファイル名を含む。既存下書きを上書きしない。auto-sendの既存挙動を確認する。
- 回帰: Dropbox InputとGitHub Inputの選択状態・ツリー・更新がDropbox Outputと相互に干渉しないことを確認する。

### 手動受け入れテスト

- Dropbox root、深い階層、空フォルダを保存先に指定し、表示パスとコピー内容を確認する。
- 同一フォルダで複数回保存依頼し、再取得した既存名に応じて `-vN` が増えることを確認する。
- アクティブフォルダを開いたまま別フォルダを展開しても、保存先が変わらないことを確認する。
- 読み込み済みDropboxファイルを候補に選んでも、出力先が自動変更されず、新規バージョン名になることを確認する。
- GitHubのみを使った会話ではDropbox出力候補が生成されないことを確認する。
- ChatGPT側Dropbox書き込みが使える環境と使えない環境で、Primitive IOが保存成否を断定しないことを確認する。
- Dropbox APIのNetworkを確認し、Output操作でファイル本文・upload・書き込みリクエストが発生しないことを確認する。

## 9. 完成条件

- Dropbox Outputで保存先フォルダ、ベースファイル名、確定済みのバージョン付きファイル名を、保存依頼前に確認できる。
- Dropbox APIから直下のメタデータ以外を取得せず、Dropboxへの直接書き込みを行わない。
- GitHub InputとDropbox Outputの状態・候補・プロンプトが混在しない。
- 既存下書きを保護し、auto-sendはユーザーが保存依頼を押した場合だけ実行する。
- ChatGPTまたはDropboxの保存結果をPrimitive IOが成功・失敗として表示しない。

## 10. v0.3.0で含めないもの

- Dropboxファイル本文の取得・保存・アップロード・上書き・削除
- GitHubへの出力、GitHubファイルを出力候補にする機能
- ChatGPT回答やDropbox保存結果の取得・解析・成功判定
- 出力内容の選択、会話の一部指定、ユーザー登録の定型プロンプト
- Dropbox上の原子的な競合検出・予約・自動リトライ
- 複数フォルダへの同時保存、Dropbox共有設定の変更

## 11. 将来候補

- 保存内容を指定するユーザー登録の定型プロンプトと、その選択UI
- 最新のChatGPT回答だけ、選択範囲だけ、または会話全体を保存する内容モード
- Dropboxメタデータを利用したバージョン名候補のプレビュー更新
- 明示的な別名指定・日付形式・ユーザー定義のバージョン命名規則
- Dropboxへの直接書き込みを行う場合の、別OAuth scope・最小権限・競合防止・セキュリティレビュー
