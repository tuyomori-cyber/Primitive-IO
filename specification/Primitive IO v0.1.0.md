# Primitive IO — MVP仕様

- 文書版: v0.1.2
- 作成日: 2026-09-21
- 状態: 構想・MVP仕様
- 対象: Firefox / ChatGPT Web / Dropbox

## 1. 概要
ChatGPT WebにDropboxのファイルツリーをサイドバー表示し、Dropbox上の1個または複数ファイルをGUIで選択して「読み込み」できるFirefox用ブラウザ拡張。MVPはFirefoxに限定する。

拡張自身はファイル本文をChatGPTへ貼り付けない。選択したDropboxファイルのパスから定型プロンプトを生成し、ChatGPT入力欄へ投入する。既定ではユーザーが内容を確認して送信し、任意設定で拡張がそのまま送信できる。実際の本文取得はChatGPT側のDropbox連携に任せる。

## 2. 背景・目的
通常ChatでもDropboxファイルを読み込めるが、ファイル名やパスを自然言語で指定する必要がある。本拡張はこの操作を古典的なファイル選択UIへ置き換える。

主な利用想定:
- ChatGPTで要件・仕様・設計を議論
- DropboxをWeb ChatGPTとローカル環境の橋として利用
- LinuxのDropbox同期フォルダをVS Code / Codex / 別LLMから参照
- 複数Markdown文書を横断して議論

## 3. MVP機能
### Dropbox Explorer
- ChatGPTページ上にサイドバーを追加
- Dropboxのフォルダ/ファイルをツリー表示
- フォルダの展開・折りたたみ
- rootでは直下のファイル名・ディレクトリ名を取得する
- フォルダを展開した時点で、その直下のフォルダ・ファイル名をDropbox APIから取得する（遅延取得）
- `.md` と `.txt` を読み込み対象とする。その他のファイルはツリーに表示するがグレー表示し、選択できない
- ChatGPTページ内に開閉可能なパネルとして表示する

### ファイル選択
- 1ファイル選択
- 複数ファイル選択
- 選択解除
- MVPではフォルダ自体は読み込み対象にしない
- 選択上限は5ファイル
- 選択状態はChatGPTページを表示している間だけ保持し、ページ遷移・再読込時には解除する

### 読み込み
1個以上のファイル選択時に「読み込み」ボタンを有効化する。

押下時のプロンプト例:

> Dropboxから以下のファイルを読み込み、この会話で参照できる状態にしてください。
>
> /project/新約オルガン/新約オルガン_MVP仕様_v0.1.2.md
> /project/新約オルガン/部品一覧_v0.2.md

プロンプトをChatGPT入力欄へ投入する。既定では送信せず、ユーザーが確認して送信する。「自動送信」を明示的に有効にした場合だけ、投入後に拡張が送信する。

## 4. MVPに含めないもの
- Dropbox本文の拡張による取得・貼り付け
- ChatGPT回答の取得・解析
- Dropboxへの保存
- 既存ファイルの上書き
- バージョンアップ保存
- 新規Markdown保存
- 差分表示
- 更新対象文書の自動判定
- Skillによる文書管理
- Chromium対応
- 他LLMサービス対応
- ローカルファイルへの直接アクセス

## 5. アーキテクチャ
```text
Firefox Extension
 ├─ Dropbox API
 │   └─ フォルダ/ファイル名/パス取得
 │
 └─ ChatGPT Web UI
     └─ 読み込みプロンプト投入・送信
             ↓
          ChatGPT
             ↓
       Dropbox連携
             ↓
          Dropbox
             ↓
       Linux公式同期
             ↓
 VS Code / Codex / ローカルLLM
```

### 責務
**Extension**
- Dropboxツリー表示
- 選択状態管理
- パス取得
- プロンプト生成
- ChatGPTへのInput投入・送信
- 接続中Dropboxアカウントの表示

**Dropbox API**
- OAuth認証
- ディレクトリ一覧・ファイル名・パス取得

**ChatGPT**
- 指定Dropboxファイルの本文取得・理解
- ユーザーとの議論

**Dropbox**
- 文書の永続化
- Web ChatGPTとローカル環境の橋渡し
- Linux同期

## 6. 設計原則
### 拡張を薄くする
拡張はファイル内容を理解せず、「GUIで指定したDropboxパスをChatGPTへの自然言語命令へ変換する」ことに徹する。

### ファイル本文を運ばない
本文はChatGPT自身のDropbox連携に取得させる。

### Outputを扱わない
MVPではChatGPTの生成結果をDOMから取得・解析・保存しない。ユーザー操作を契機としたInput側の補助を中心とする。

### DOM依存を隔離
ChatGPT入力欄・送信操作へのDOM依存部分は専用モジュールへ隔離し、ChatGPT UI変更時の修正範囲を限定する。

既定の動作は入力欄への投入までとし、送信はユーザーが行う。自動送信は明示的に有効化した場合のみ行う。

## 7. Dropbox認証
ブラウザ拡張からDropbox APIへOAuth認証する。rootから任意のフォルダを参照するため、Dropboxアプリのアクセス種別は **Full Dropbox** とする。MVPでは一覧参照のみなので、以下の必要最小限の読み取り権限を要求する。

- `files.metadata.read` — ファイル・フォルダ名、パス、IDなどのメタデータ取得
- `account_info.read` — 接続中アカウントの表示

`files.content.read` は要求しない。拡張はDropboxのファイル本文を取得・保存せず、書き込みも行わない。

認証方式は、Firefox拡張を公開クライアントとして扱う OAuth 2.0 Authorization Code Flow with PKCE とする。Dropboxアプリのクライアントシークレットは拡張へ含めない。ユーザーのログイン状態は維持するため、リフレッシュトークンをFirefox拡張のローカル保存領域に保持し、必要に応じて短命のアクセストークンを更新する。認証情報はbackground処理だけが扱い、ChatGPTページへ注入するスクリプトには渡さない。接続解除時はローカルの認証情報を削除する。

ChatGPT側のDropbox連携と拡張側OAuthは別の認証である。MVPの前提条件として、両者は同一または同等の閲覧権限を持つDropboxアカウントでなければならない。拡張は接続中アカウントを表示するが、ChatGPT側アカウントとの自動照合は行わない。

## 9. 操作フロー
### 単一ファイル
1. ChatGPTを開く
2. Dropboxサイドバーでフォルダを展開
3. ファイルを選択
4. 「読み込み」
5. 拡張が定型プロンプトをChatGPT入力欄へ投入
6. ユーザーが確認して送信（自動送信を有効にした場合は拡張が送信）
7. ChatGPTがDropboxから本文を取得
8. 通常通り議論

### 複数ファイル
1. 複数ファイルを選択
2. 「読み込み」
3. 全選択パスを含む1プロンプトをChatGPT入力欄へ投入
4. ユーザーが確認して送信（自動送信を有効にした場合は拡張が送信）
5. ChatGPTが各ファイルを取得
6. 文書を横断して議論

## 10. エラー表示
最低限以下を区別する。
- Dropbox未認証
- Dropbox API取得失敗
- フォルダ一覧取得失敗
- ファイル未選択
- 選択上限超過
- ChatGPT入力欄を検出できない
- ChatGPTへの送信失敗

ChatGPT側のDropbox読み込み失敗は通常のChatGPTメッセージに任せ、拡張は回答内容から成否判定しない。

## 11. セキュリティ・プライバシー
- Dropbox権限は必要最小限
- 認証情報を独自外部サーバーへ送らない構成を優先
- OAuthの認証情報はbackground処理だけで扱い、ChatGPTページのDOMへ渡さない
- リフレッシュトークンはFirefox拡張のローカル保存領域に保持し、接続解除時に削除する
- ファイル本文を拡張側で保存しない
- ChatGPT回答を収集しない
- ファイル名・パスは、読み込みプロンプトの一部としてChatGPTへ送信される
- MVPではテレメトリなし
- ユーザー操作なしの自動巡回・自動送信なし

## 12. 対象環境
- Firefox用ブラウザ拡張（MVPはFirefoxのみ）
- Linux / Xubuntu
- ChatGPT Web
- Dropbox
- Markdown中心

GitHub等での小規模公開を想定。Chrome、Chromium、Firefox以外のブラウザ、および各ストアでの一般公開はMVP対象外。Firefox固有APIを利用してよく、クロスブラウザ互換性はMVPの設計制約としない。Chromium対応は需要が生じた場合に別途検討する。

## 13. 将来候補
### 新規保存
Dropboxディレクトリを選択し、会話内容をMarkdownとして新規保存するようChatGPTへ指示する。

### 次版保存
既存ファイルは上書きせず、`v0.1.2 → v0.1.3` のようにバージョン番号を上げた完全版を新規作成する。

### 複数文書の次版作成
会話が複数ファイルを横断した場合、関連する各文書を次版として新規作成する。変更対象の意味判断は拡張ではなくChatGPT/Skill側へ持たせる。

### 保存前確認・差分
更新対象、元ファイル、新ファイル名、変更概要を提示し、確認後に保存する。必要になれば実diffも検討。

### Skill
将来的に文書管理ルールをSkillへ分離する候補:
- 既存ファイルは上書きしない
- 更新は必ずバージョンを上げて新規作成
- 会話中の決定を関連文書へ適切に振り分ける
- 必要に応じ保存前に変更予定を提示する

## 14. MVP完成条件
- FirefoxのChatGPTページにDropboxサイドバーを表示
- Dropbox OAuth認証成功
- rootおよび展開したフォルダの直下を閲覧可能
- `.md` / `.txt` の1個から5個を選択可能
- 「読み込み」で適切なプロンプトを生成
- ChatGPT入力欄へ投入可能。明示設定時は送信可能
- ChatGPT側Dropbox連携で対象ファイルを取得可能
- 読み込み後、そのまま通常チャットを継続可能

## 15. 位置づけ
ChatGPTの代替クライアントや独自LLMクライアントではない。ChatGPT Webが既に持つDropbox読み込み能力に対して、Dropboxの実ディレクトリ構造をGUIとして追加する小さなUX改善ツール。

中心思想:

**「自然言語でファイルパスを指定する操作を、ファイルツリーから選ぶ操作へ戻す」**
